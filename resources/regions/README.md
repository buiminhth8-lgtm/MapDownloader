# 行政区边界数据（`resources/regions/`）

这个目录是**放数据的地方**，仓库里**只有这份说明**，不带任何边界文件。

## 这里要放什么

| 文件名 | 用途 | 谁提供 |
| --- | --- | --- |
| `china.geojson` | 「行政区域 → 中国」这个预设的裁剪边界 | **你自己**（见下面的授权要求） |

放好之后，在界面上把「区域类型」切到**行政区域**、行政区选**中国**，
候选范围框会自动填上边界的外包矩形（只读），点「计算」就会给出
**候选 / 区域内 / 过滤 / 占比**四个数字 —— 真正要下载的是**区域内**那一份。

## 授权要求（重要）

> 中国国界属于**法定地图内容**，必须使用带**审图号**的合法授权 GeoJSON 数据。

本项目**不内置、不生成、也不套用**任何中国国界数据。原因很直接：

- 国界画错了不是"精度问题"，是**地图合规问题**；
- 从网上随手拿一份 `china.geojson` 塞进来，没有人能保证它的来源与审图号；
- 因此本工具只提供"规范路径 + 加载器 + 缺失时的明确报错"，
  数据由使用者自己按授权渠道取得。

缺文件时程序会**明确报错**并告诉你文件该叫什么、放哪，**不会**退化成按外包矩形下载
—— 那会静默下一大片境外瓦片，而你在界面上看不出来。

## 文件格式

标准 GeoJSON，顶层可以是 `FeatureCollection` / `Feature` / 几何对象本身；
面几何支持 `Polygon` 与 `MultiPolygon`。建议在 `properties` 里写上版本，
便于日后追溯"这批瓦片是按哪版边界裁的"：

```json
{
  "type": "Feature",
  "properties": {
    "name": "中国",
    "id": "china",
    "boundaryVersion": "2026-09"
  },
  "geometry": { "type": "MultiPolygon", "coordinates": [ [ [ [116.0, 39.0], "…" ] ] ] }
}
```

几条约定：

- **必须是 UTF-8**（无 BOM 也可以）。带别的编码会直接报错，不做猜测转码。
- `properties.boundaryVersion` 会随任务记录与 MBTiles metadata 一起写下去，
  最后进地图包 manifest 的 `region.boundaryVersion`。**两批瓦片能不能续着下、
  一个包是不是按同一版边界裁的，就靠它**。
- **不接受跨 180° 经线的几何**：本工具的瓦片数学是单块的 Web Mercator，
  跨经线的区域会被拒绝（而不是悄悄裁掉一半）。
- 自相交的几何默认拒收；确实需要时可以走"尝试修复"（buffer(0)），
  但修复结果会如实记进日志。

## 自测

放好文件后，不必先跑一次真下载：

```bash
# 只看加载器能不能读、外包矩形是多少
.venv/Scripts/python.exe -c "from app.geo import CHINA_REGION_PRESET as p; d=p.load_document(); print(d.geometry.bounds)"
```

或者在界面上点一次「计算」—— 它会把候选 / 区域内 / 过滤三个数字都列出来。

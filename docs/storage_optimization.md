# MBTiles 存储优化与区域分包（Slice 38）

对已经下载的 PNG/JPEG 栅格地图执行本地压缩、图片内容去重和区域导出。
源地图只读，不使用 Token，不向地图服务请求瓦片。

## Windows 使用

从「文件 → MBTiles 压缩、去重与区域分包…」进入，或在生成地图包窗口点击「压缩/分包…」。
选择源 MBTiles、输出父目录和一个新的目录名称，选择导出方式与压缩选项，再点击：

1. **预览优化与分包**：后台检查源图、逐区覆盖、预计坐标数和磁盘空间。
2. **导出并验证**：后台压缩、写入、全量读取、检查覆盖，并按勾选生成地图包。
3. 完成后选择输出文件，可继续「检查/打包所选文件」或打开结果目录。

预览时不会创建输出目录。预览和等待导出确认期间占用共享下载通道，避免同时写入源图；
可点击取消释放。修改选项会使预览失效；按计划分包时，计划变化也要求重新预览。
输出文件统计以实际结果为准，预览不是压缩比保证。

## 三种导出范围

| 方式 | 输入与覆盖含义 |
| --- | --- |
| 完整地图优化 | 保留源图全部坐标，输出一份 MBTiles |
| 按单包覆盖规则分包 | Slice 36 单包的每条冻结规则各导出一份，保留区域与 Zoom |
| 按当前下载计划区域分包 | 使用启用条目的区域与 Zoom，再与源地图同级几何覆盖取交集 |

分包不把源图总包围框当成全域高清。源包在 Z18 只覆盖任务区时，即使计划请求一整个省，
Z18 导出也只覆盖源图实际定义的任务区。GeoJSON 孔洞和多边形相交规则保持一致；
边界瓦片保留完整像素，可能带有边界外内容。

相邻或相交规则分包会在不同文件中保留必要的重叠坐标，因此各分包的张数合计和大小
可能大于整包。每份 MBTiles 内部做内容去重，当前不跨多个独立文件共享图片表。

## 压缩与图片保护

- 默认 PNG 优化保持解码后的像素与透明度；只有编码字节更小时才替换原 PNG。
  透明调色板及合成注记保留透明效果。PNG 文本等辅助元数据不承诺逐字节保留。
- 默认 JPEG 保持源字节。主动勾选 JPEG 后，以指定质量重新编码，仅允许明确标记的
  **卫星纯底图**，不允许矢量、注记、未知模式或带透明度的图片静默转换。
- JPEG 质量可选 50～95，默认 85；这是有损操作，报告明确标记。PNG 仍是矢量和
  合成注记的输出格式，不引入设备解码兼容性尚未验证的 WebP/PBF 转换。
- 每个选中的源图片都会做完整解码，优化后的独立图片再次解码；PNG 还比对像素。
  损坏、图片与声明格式不一致或超大像素会停止导出。

JPEG 质量不是容量保证，PNG 已充分压缩或没有重复图片时，收益可能很小；去重索引
也有开销。完成界面会如实显示减少或增加，不承诺固定百分比。

## 内容去重与读取兼容性

MBTiles 的规范允许用兼容视图实现表接口，见[官方 MBTiles 规范](https://github.com/mapbox/mbtiles-spec/blob/master/1.3/spec.md#database)。
默认 `map + images + tiles VIEW`：坐标表引用唯一图片，SHA-256 相同后仍比较图片原字节。
不会因坐标相同或地图模式名称相似而把不同图片合在一起。卫星和矢量由各自源文件导出，
不会混合。也可以关闭去重，使用普通 `tiles` 实体表。

osmdroid 的官方 `MBTilesFileArchive` 以只读方式打开 SQLite，按 `tile_column`、TMS 的
`tile_row` 和 `zoom_level` 从 `tiles` 查询 `tile_data`，因此本导出保持这套列名和坐标约定。
依据：[osmdroid 官方读取实现](https://raw.githubusercontent.com/osmdroid/osmdroid/master/osmdroid-android/src/main/java/org/osmdroid/tileprovider/modules/MBTilesFileArchive.java)
（核对日期：2026-10-24）。

导出器对**每个输出坐标**重放相同查询，包括 Android 代码使用的浮点行号字符串，
并校验取回的图片。现有 Windows 读取器、检查器、地图包生成与 SHA256 验证也会运行。
这属于读取契约与真实 SQLite 验证，不等于 Android Bitmap/MapView 真机显示验收；
当前仓库没有完整 Android 应用。若设备导入器另外要求 `tiles` 必须是实体表，可关闭去重。

## 原图、派生文件与完整性

优化仅写新目录，已有目录不会覆盖，源图不改名、不删除、不执行 VACUUM。
预览会拒绝仍有未合并 WAL 数据的源图，要求先停止写入；导出迭代持有 SQLite 只读快照。
后台处理采用有界缓存、逐瓦片解码和批量事务，不把全部图片放入内存。

源图缺瓦片或抽样发现损坏时，须先补齐/修复再导出。选中数据的后续完整解码、计数或
覆盖检查失败也会终止。旧多边形包缺少边界资源时，完整优化可保留原区域声明并报告
覆盖未知；区域分包必须有可还原边界，不允许猜成矩形。Slice 36 快照可直接移机读取。

导出文件有 `export_readonly=true`、`export_tile_count`、`storage_layout` 和 `optimization`
元数据。检查器校验固定瓦片数、去重引用和坐标唯一性；JOIN 隐藏掉的坏引用也会报错。
导出物用于读取/交付，不能直接续传或修复，应修复原下载文件后再导出，避免原任务与
派生编码混写。导出文件可以再次作为只读输入，重新优化或继续分包。

## 空间、取消与报告

Windows 入口继承 Slice 37 设置的每盘保留空间，独立 API 默认为 256 MiB。
预览估计写出文件、索引和可选完整打包副本所需空间；启动前和流式写入期间再次检查。
外部程序仍可能占用磁盘，估算不能替代实际磁盘错误处理。

先在新目录旁的私有暂存目录生成所有文件，校验全部通过后再整体发布。
取消、写入失败、空间不足或目的目录被占用会清理本轮暂存结果，源文件与已有产物保留。
发布完成后的迟到取消不会将成功结果误报成未导出。进程被强制结束时可能留下未发布的
隐藏暂存目录，关闭相关进程后可按报告/目录名确认，再手动清理。

`export_report.json` 区分：

- `sourceFileBytes` / `outputFileBytes` / `savedFileBytes`：原 MBTiles 与输出 MBTiles 合计比较；
- `deliveredBytes` / `deliveredSavedBytes`：包含打包副本、manifest 和报告的全部交付文件；
- 每文件的坐标数、独立图片数、图片输入字节、实际存储图片字节及地图包相对路径；
- `lossy` 与 `androidDeviceVerified`：是否进行了有损转换、是否做过 Android 真机验收。

默认生成地图包会额外保存一份文件副本，不能把单份 MBTiles 减少量当成整个目录的节省量。

## 离线验收

```powershell
.venv/Scripts/python.exe -B -m pytest -q tests/test_storage_optimization.py tests/test_storage_optimization_ui.py
.venv/Scripts/python.exe -B scripts/verify_storage_optimization.py
.venv/Scripts/python.exe -B scripts/verify_stability.py
```

合成区域与重复 PNG 的验收验证实际文件减容、源文件字节不变、透明像素一致、
osmdroid 查询、普通表/去重视图、规则分包无漏图和打包校验；回归覆盖两种地图模式、
JPEG 保护、源损坏、覆盖交集、取消/失败/磁盘变化、产物只读及界面实际后台链路。

# 下载容量预算与预测（Slice 37）

下载前判断本次地图或下载计划预计占用多少空间、还需下载多少，以及是否超过预算。
预测完全读取本地数据，不使用 Token，不向地图服务发送抽样请求。

## 使用入口

- 下载面板「容量预算与预测…」，或「文件 → 下载容量预算与预测…」：预测当前配置。
- 下载计划窗口「容量预算」：预测启用条目，分别统计目标文件，再汇总。
- 默认在启动下载、续传和开始计划前自动检查。预算内且磁盘足够时自动继续，
  超预算时显示预测窗口；原有任务风险确认仍然执行。

可设置本次下载/计划预算（默认 64 GiB）、每个磁盘的保留空间（默认 2 GiB），
以及是否同时预留同盘生成一份完整打包副本。点击「重新预测并保存设置」记住偏好。
关闭「下载前自动检查预算与磁盘空间」只关闭自动预检，手动入口仍然可用。

预算是本次选择的地图文件合计；设备端所有地图的全局配额、缓存清理属于 Slice 40，
当前不会自动删除旧地图、备份或任何其他任务的文件。

## 预测依据

先按现有 Polygon 相交规则或矩形范围计算逐 Zoom 的目标瓦片数。中国区域的边界
筛选规则没有改变；容量优化不会切换成中心点筛选，也不会扩大为矩形下载。

优先从目标文件和同输出目录的 MBTiles 抽样，匹配地图类型、注记合成方式和 Zoom。
抽样有文件数和每级样本数上限，按瓦片列分散取样，只查询图片长度，不读取整块 BLOB，
不请求网络。不同模式、不同注记方式、不同 Zoom 的样本不混用。

缺少同级别样本时明确使用默认模型：矢量 30 KiB/张；卫星纯底图 96 KiB/张、
卫星合成注记 128 KiB/张。新文件有基础数据库空间预留，并计算索引等额外开销。
样本少时放大保守估计；样本分布不均时也增加余量。

这些值是估算，不是容量保证。实际区域内容、图源、编码、SQLite 页分配都会影响结果。
当前模型没有执行图片压缩、内容去重或跨包去重，也不会把这些尚未完成的节省量算进去。

## 续传与磁盘空间

报告分别显示目标张数、已有张数、新增张数、预计请求次数、新增文件容量和最终容量。
已有张数只计当前范围与 Zoom 内的坐标；不把区域外的历史数据算成已完成目标。
已存在文件本身的实际大小仍计入最终容量，包括文件中保留的其他层级数据。

注记合成每张新增瓦片预计两次 HTTP 请求，纯底图一次；请求数不包含重试、损坏瓦片
重下载或源站更新。容量预测不等同于下载时间或账号配额承诺。

不同磁盘分别检测，保留空间在同一个盘只计一次。同盘打包副本使用完整预计成品大小，
不能只预留本次新增的部分；异盘打包需要另行检查目标盘。未知或不足的磁盘空间会禁止
当前预测结果的「确认继续下载」，需调整并重新预测。预测完成后外部程序仍可能占用空间。

## 超预算与裁剪建议

超出保守估计预算时，可以返回调整，或明确选择继续；磁盘不足时不能通过继续按钮绕过。
报告列出降低具体条目最高 Zoom 能少新增多少容量，也提示优先缩小主要高清区域或航线
缓冲半径。缩小几何后的节省量需要重新估算，不用面积比例冒充精确瓦片数。

「采用所选 Zoom 建议并返回调整」是用户主动操作，不会立即下载。单任务回填新的 Zoom
和地图名称，保留旧任务及旧文件；计划会修改相应条目并作废旧估算。已有未结束执行记录
的计划须先处理执行记录，不能直接改变执行中的任务范围。

降低 Zoom 只减少尚未下载的部分，不删除已有高层级瓦片，因此不能宣称立即回收已有容量。
预测过程中变更配置，旧结果不能用于启动下载。预测可取消，关闭窗口会等待线程安全结束。

## 离线验收

```powershell
.venv/Scripts/python.exe -B -m pytest -q tests/test_storage_budget.py tests/test_storage_budget_ui.py
.venv/Scripts/python.exe -B scripts/verify_storage_budget.py
.venv/Scripts/python.exe -B scripts/verify_stability.py
```

覆盖两种模式与注记隔离、逐级抽样与模型回退、续传扣除、数据库空间、分盘预算、
打包副本、预算确认、磁盘拦截、配置变更失效、用户主动采用建议、预测取消以及
「预算预检 → 下载部分成功 → 失败 → 再预测 → 续传成功」的真实 SQLite 闭环。


## 与 Slice 36 单包覆盖联动

「单包覆盖下载…」始终先显示一次容量预览，按每个 Zoom 的区域并集统计，重叠坐标
不重复计数。预算包含新 MBTiles 中策略元数据；磁盘预留额外包含一次本地策略侧文件。
已有单包只扣除规则内坐标，不将原计划独立分包的瓦片当成单包已完成。
单包建议描述整体最高 Zoom，需返回计划逐区域调整后重新预览，避免静默丢弃高精度任务区。

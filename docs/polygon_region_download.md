# 按行政区域（GeoJSON 多边形）下载瓦片

> Slice 16。本文说清四件事：**它在解决什么问题**、**界面上怎么用**、
> **数字都是怎么算出来的**、**怎么验收**。
>
> 相关文档：包格式见 [`map_package_v1.md`](map_package_v1.md)；
> 端到端清单见 [`e2e_acceptance_checklist.md`](e2e_acceptance_checklist.md)；
> 边界数据从哪来见 [`../resources/regions/README.md`](../resources/regions/README.md)。

## 1. 为什么需要它

矩形范围与行政区边界从来不是一回事。北京主城的矩形外包框会一起框进来：

- 河北的固安、三河、涿州 —— 一百多公里外；
- 出海口那一片；
- 按矩形下的"北京市"离线包，**瓦片数比实际需要多四成**，多出来的全是不该下的。

多下的瓦片不是"浪费一点点"：它花你的天地图配额、占你的手机存储、
拖长下载时间，而且**在界面上完全看不出来**——用户看到的只是一个"更大的矩形"。

所以这一版引入的是：**候选范围（外包矩形）只用来缩小搜索面，真正要下的瓦片
是"与行政区域几何相交"的那些。**

## 2. 两个概念，一个数字

| 名字 | 含义 | 谁用它 |
| --- | --- | --- |
| **候选瓦片**（candidate） | 外包矩形覆盖的瓦片数。**只是搜索面** | 只用来给用户做对照 |
| **区域内瓦片**（selected） | 候选里**真正与区域相交**的瓦片数 | 进度条分母 / 大任务提示 / 容量预估 / 任务记录 / 续传 |
| 过滤瓦片（filtered） | `候选 − 区域内` | 界面上的一行对照 |

**所有下游计算都只用「区域内」那一个数**。用候选数去当分母，你会得到一个永远
走不满的进度条（"46 张下了 46 张，怎么才 56%"），以及一个虚高的容量预估。

判"相交"用的是几何库的 prepared geometry + `intersects`，**不是**"瓦片中心点
在不在区域内"：

- 按中心点判，边界上的瓦片会被整片丢掉 —— 地图边缘出现一圈锯齿状空洞；
- 按 `intersects` 判，只要瓦片与区域有重叠就留下。**多留一张无害，少留一张是
  用户看不见的数据缺失**，两者代价不对称。

## 3. 界面上怎么用

1. 「区域类型」选 **行政区域**（另一个选项是 **自定义矩形**，行为与以前完全一致）；
2. 「行政区」选 **中国**；
3. 四个经纬度框会**自动填上边界的外包矩形并变成只读** —— 范围由数据文件决定，
   手改会让"界面显示的范围"与"实际裁剪依据"对不上，而用户看不出这一点；
4. 点 **计算**，结果区给出：

```text
区域：中国
候选瓦片：81
区域内瓦片：46
过滤瓦片：35
过滤比例：43.2%
预计 WMTS 请求：92（46 张 × 底图+注记 2 层）
预计容量：1.35 MB
Zoom：12 ~ 12
地图类型：矢量地图 + 中文注记
Zoom 明细（候选 / 选中 / 过滤）：
  z12  81 / 46 / 35
输出文件：…\output\china.mbtiles
```

5. 点 **开始下载**。区域外的瓦片**在发出 HTTP 请求之前**就被丢掉：既不消耗
   天地图配额，也不进任何计数（不算失败、不算跳过）。

### 边界文件不在时

行政区域模式下如果 `resources/regions/country/china.geojson` 不存在，会**明确失败**：

```text
计算失败：行政区域不可用：行政区边界文件不可用：…\resources\regions\country\china.geojson。
中国国界属于法定地图内容，请使用带审图号的合法授权 GeoJSON 数据，
放到 …\resources\regions 下的 country/china.geojson（相对路径）后重试
```

（文件的相对路径由 `resources/regions/index.json` 里那条记录决定，
见 [region_catalog.md](region_catalog.md)。）

**它不会退回按矩形下载。** 退回去的后果是静默下一大片境外瓦片，而用户在界面上
只会看到一个"正常"的数字。宁可停下来问，也不要悄悄多下。

## 4. 数字是怎么算出来的

- **外包矩形**：`geometry.bounds`（GeoJSON 的几何包围盒），再转成瓦片编号区间；
- **候选瓦片**：`calculate_tile_range(bounds, zoom).tile_count` 逐级求和；
- **区域内瓦片**：对候选区间里每一张瓦片，用 `shapely.prepared.prep()` 预编译的
  几何做 `intersects` 判定，命中才计入；
- **过滤比例**：`过滤 / 候选 × 100`。

实现上全程是**流式**的：候选区间只以整数保存（`min_x..max_x`），
不会把几百万张瓦片的坐标列表物化到内存里。

## 5. 与旧功能的兼容

| 场景 | 行为 |
| --- | --- |
| 自定义矩形 | **逐位不变**：不构造过滤器，`selected == candidate`，不写 `region_id` |
| 老任务续传 | 任务记录里没有 `region_type` → 按矩形处理，与 Slice ≤15 一致 |
| 老的 MBTiles | metadata 里没有 `region_type` → Inspector 走矩形口径 |
| 多边形任务续传 | 按记录的 `region_type` / `region_id` 还原区域；**已有瓦片只数区域内那些** |
| `tasks.json` | 只写 `region_type` / `region_id` / `boundary_version` 三个字段，**不写 GeoJSON**（一份省级边界有几 MB） |
| 地图包 manifest | 新增**可选** `region` 子对象；老文件打出来的包与以前逐字节一致 |

续传还要多一层：**边界版本对不上要提醒**。同一块地按 2026-03 与 2026-09 两版
边界裁出来的瓦片集合可能不同，硬续会在区域边缘留下一圈"哪版都不算"的瓦片。

## 6. Inspector 怎么判一个多边形包

多边形包的"期望瓦片数"必须**按几何算**：

- 按几何算：中国包期望 46 / 实际 46 → PASS；
- 按外包矩形算：期望 81 / 实际 46 → 报"缺了 35 张" —— 而这个包是**完整**的。

所以边界文件不可用时的处置是：覆盖度标 **未知（UNKNOWN）** 并给一条 WARNING，
**不退回矩形口径**。误报比"不知道"糟糕得多：用户会照着去重下几万张。

### 手工 GUI 验收（13 步）

脚本把下面这些全部自动走了一遍（`--offscreen` 之外的运行会截图存证）。

| # | 操作 | 期望 |
| --- | --- | --- |
| 1 | 启动工具，看「区域类型」 | 默认「自定义矩形」 |
| 2 | 矩形模式下看四个经纬度框 | 可编辑 |
| 3 | 填范围点「计算」 | 结果区给的是瓦片数，**没有**「区域内」那几行 |
| 4 | 切到「行政区域」（边界文件没放） | 四个框变只读；提示区显示"边界不可用…" |
| 5 | 看结果区 | 上一轮矩形算出的数字**立刻消失**，退回占位 |
| 6 | 点「计算」 | 明确失败：文件叫什么、放哪、要授权数据 |
| 7 | 按提示放好 `country/china.geojson`，切走再切回 | 候选范围框自动填上外包矩形 |
| 8 | 点「计算」 | 候选 / 区域内 / 过滤 / 占比 / 请求量 / 容量都给全 |
| 9 | 核对「区域内」== 进度条分母 | 用候选数当分母是本 Slice 最典型的缺陷 |
| 10 | 开始下载 | 区域外的瓦片**一张都不请求**；失败与跳过都是 0 |
| 11 | 下载完看任务记录 | 里面有 `region_type=polygon` / `region_id` / 边界版本 |
| 12 | 对产物跑「检查 MBTiles」 | 期望值按几何算；完整包判 PASS，缺失 0 |
| 13 | 生成地图包后看 manifest | 有 `region` 子对象，位置紧跟 `bounds` |

第 5 步是**本地实测抓到的真缺陷**的回归点：切到行政区域后，结果区里那句
"预计瓦片 56"曾经还在（看起来就像行政区域也算出了 56 张），而且接下来只要动一下
输出目录，那句"计算失败"还会被缓存里的旧结论盖回去。修复方式是在区域变更时
作废预估缓存（`MainWindow._on_region_changed`），回归用例见
`tests/test_ui_smoke.py`。

## 8. 已知边界与不做的事

- **只支持单块 Web Mercator**：跨 180° 经线的几何会被拒绝（不是悄悄裁一半）；
- **自相交几何**默认拒收，可选"尝试修复"（`buffer(0)`），修复会记日志；
- **只内置「中国」一个预设**：要加省市只需在 `REGION_PRESETS` 里补一条并放入同名
  GeoJSON，其余代码（加载 / 过滤 / 预估 / Inspector 还原）无需改动；
- **不内置任何国界数据**：法定地图内容必须用带审图号的授权数据；
- **不做"按区域自动切分大任务"**：那是下一个 Slice 的事。
